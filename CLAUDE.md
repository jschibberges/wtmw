# CLAUDE.md

This file provides guidance to Claude when working with code in this repository.

## Project Overview

"Wer talkt mit wem" (Who talks with whom) is a German political talkshow analysis platform that scrapes, analyzes, and visualizes guest appearances across major German political talkshows (Anne Will, Caren Miosga, Hart aber Fair, Markus Lanz, Maischberger, Maybrit Illner). The project uses NLP topic modeling and network analysis to identify patterns in guest appearances, political affiliations, and discussion topics.

## Development Workflow

### Data Pipeline (Execute in Order)

1. **Scraping**: `python scrape_talkshows.py`
   - Scrapes episode data from fernsehserien.de for all six talkshows
   - Creates/updates JSON files in `data/` directory (one per show)
   - Generates unique episode IDs (UIDs) via URL hashing to prevent duplicates
   - Extracts: episode metadata, descriptions, dates, guests with roles/parties

2. **Analysis**: `python analyze_talkshows.py`
   - Loads all JSON files and performs comprehensive analysis
   - **BERTopic Hyperparameter Tuning**: Automatically runs if no valid parameters exist or document count has grown significantly (≥20% growth)
   - **Topic Modeling**: Uses BERTopic with German text preprocessing (lemmatization, POS filtering)
   - **Guest Classification**: Cleans guest names, consolidates duplicates, assigns categories and topics
   - **Embedding Fallback**: Guests without rule-based category get classified via embedding similarity
   - **Network Analysis**: Builds co-occurrence networks for guests and topics
   - Outputs Excel files and visualizations to `data/`

3. **Visualization**: `streamlit run app.py`
   - Launches interactive dashboard at http://localhost:8501
   - Requires files generated by `analyze_talkshows.py`

### Key Generated Files

All files are created in the `data/` directory:

- `{ShowName}_data.json` - Raw scraped data per show
- `all_data_with_topics.xlsx` - Main analysis output with topic assignments
- `guests_with_topics.xlsx` - Guest appearances with topic labels
- `guest_topic_range.xlsx` - Guests ranked by topic diversity
- `best_parameters.json` - Optimized BERTopic hyperparameters
- `name_corrections.json` - Manual guest name override mappings
- `topic_labels.json` - Human-readable topic label overrides (edit to rename topics)
- `talkshow_topic_model/` - Saved BERTopic model (safetensors format)
- `cooccurrence_network.png/html` - Guest co-appearance network
- `topic_cooccurrence_network.png/html` - Topic connection network
- `topics_*.html` - Interactive BERTopic visualizations

## Architecture

### Core Modules

**scrape_talkshows.py**
- Web scraping utilities using BeautifulSoup and requests
- German date parsing (`standardize_date`) with locale handling
- Party extraction from guest descriptions using regex + normalization map
- `PARTY_STRINGS` includes: CDU, CSU, SPD, FDP, AfD, BSW, DIE LINKE, Linke, freie_wähler, parteilos
- Name cleaning: removes titles (Prof., Dr.), extracts party affiliation
- Duplicate prevention via UID hashing (SHA256 → base64 → 8 chars)
- `uids` stored as a `set` (not list) for O(1) lookup
- Module-level JSON loading moved into `_load_existing_data()` to avoid side effects on import
- `_SHOW_NAME_NORMALIZATIONS`: dict that maps scraped show name variants to their canonical form (e.g. `"Hart Aber Fair"` → `"hart aber fair"`); applied in the episode-detail parser so the `show` field is always consistent regardless of how fernsehserien.de capitalises the title

**analyze_talkshows.py**
- **Topic Modeling Pipeline**:
  - Hyperparameter tuning via grid search (UMAP + HDBSCAN)
  - Scoring: balances silhouette score, outlier ratio, topic count (target: 20-60)
  - Uses `intfloat/multilingual-e5-base` embeddings with MPS/CUDA/CPU auto-detection
  - Memory-safe encoding with progressive batch size reduction on OOM (64→32→16→8→4→2→1); prints a visible warning when falling back to CPU
  - Dynamic topic modeling over time (manual binning, no pandas Interval issues)
  - After `topic_model.save()`, overwrites `topics.json` with cleaned representations (role filter + dedupe applied)
- **Guest Consolidation**: Merges duplicate guests using `nlp_utils.clean_guest_rows`; aggregates `party_norm` and `role_clean` (not raw `party`/`role`)
- **Guest Classification**: `add_classification_columns(df, role_col="role_clean")` — uses cleaned role column
- **Embedding Fallback**: `apply_embedding_fallback()` from `guest_classification_embedding.py` classifies remaining unclassified guests
- **Network Analysis**: NetworkX graphs weighted by co-appearances or shared guests
- **Exports**: Interactive PyVis networks and static Matplotlib plots
- Exception handling uses specific types (`AttributeError`, `RuntimeError`) rather than bare `except Exception`

**nlp_utils.py**
- German NLP preprocessing using spaCy (`de_core_news_md` or `de_core_news_sm`)
- Stopwords: Combines solariz + stopwords-iso sources with custom domain terms (`GERMAN_EXTRA_STOP`)
- `GERMAN_EXTRA_STOP`: includes talkshow meta-verbs ("äußert", "spricht", "analysiert" etc.) to prevent them appearing as topic terms
- `TOPIC_ROLE_STOP`: frozenset of ~64 German job/role titles (Politiker, Vorsitzende, Journalist, …) filtered from topic representations and description cleaning
- `clean_guest_rows`: Multi-stage rejection (trailing parens, org patterns, junk words, role words)
- `clean_description_for_labels`: Lemmatization + POS filtering; configurable via `LiteConfig`
- `LABEL_CONFIG`: Preset with `keep_pos=("NOUN", "PROPN", "ADJ")` — excludes verbs for cleaner topic labels
- `_filter_topic_terms`: Removes `LOW_INFORMATION_LEMMAS` and `TOPIC_ROLE_STOP` entries from topic representations
- Topic term deduplication via `_dedupe_topic_terms`: removes shorter n-grams that are subsets of longer kept phrases
- Configurable via `LiteConfig` dataclass

**guest_classification.py**
- Rule-based guest classification into 9 categories (Politics, Media, Academia, Business, etc.)
- `RULES` dict with `strong` / `weak` regex patterns per category
- Weights: `STRONG_W=3.0`, `WEAK_W=1.0`, `PARTY_W=4.0`
- Confidence: `0.65 * (best_score / 7.0) + 0.35 * (best - second) / best`
- `add_classification_columns(df, role_col="role_clean")` — accepts explicit role column name
- Role-list parsing uses `except (ValueError, SyntaxError)` rather than bare `except Exception`

**guest_classification_embedding.py**
- Embedding-based fallback for guests without rule-based category
- `CATEGORY_PROTOTYPES`: 5 representative German texts per category
- `CATEGORY_MIN_SIMILARITY_OVERRIDES`: per-category minimum cosine similarity thresholds
- "Citizens & Everyday Voices" override at 0.62 to prevent catch-all behaviour
- Guests with a `party_norm` value cannot be classified as Citizens
- `CategorySource` column tracks whether classification came from 'rules' or 'embedding'

**app_helpers.py**
- Uses `logging` module (`_log = logging.getLogger(__name__)`); no bare `except Exception: pass`
- `_load_topic_labels()`: reads `data/topic_labels.json` (cached via `@lru_cache`); logs a `WARNING` on `json.JSONDecodeError` instead of silently returning `{}`
- `format_topic_label(label)`: returns human-readable topic name; both `None`/empty input and topic `-1` resolve to `"Nicht klassifiziert"` — there is intentionally only one "unclassified" label
- `prepare_guest_metadata(df)`: builds per-guest summary table with primary party and role history
- `summarize_topic_counts(df)`: sets both `topic == -1` (BERTopic outlier) and `topic == NaN` (no description, never analysed) to `"Nicht klassifiziert"` in one combined mask
- `_summarize_roles(role_list)`: collapses role list to concise summary string

**app.py**
- Streamlit dashboard using `st.radio()` navigation with `key="main_navigation"` — **intentionally not `st.tabs()`**, which resets to the first tab on every rerender
- `width="stretch"` used throughout (replaces deprecated `use_container_width=True`)
- Six tabs:

| Tab | Content |
|-----|---------|
| 📊 Übersicht | Global metrics, show coverage table, guest category distribution chart (CategoryPrimary), topic distribution bar chart (classified only) + full table in expander |
| 🕸️ Netzwerke | Sub-radio for Gäste-Netzwerk / Themen-Netzwerk / BERTopic-Visualisierungen; all interactive HTML files loaded on demand via toggle |
| 🏆 Rankings | Timeframe filter, top-10 bar charts (Auftritte + Themenvielfalt), top-25 tables, full tables in expander |
| 🔍 Personen | Timeframe filter, person selector (built from filtered data), appearance list, topic summary, co-guest analysis (bar chart + table, joined via UID) |
| 🗂️ Themen | Timeframe filter, topic selector, temporal trend chart (episodes per month), episode list, top-guest table |
| ℹ️ Über das Projekt | Project description, tech stack, pipeline steps, classification and topic modelling explanation |

- Caching: `@st.cache_data(ttl=3600)` for data loading and HTML file content
- DataFrame column access uses `if "col" in df.columns` guards — never `df.get("col", ...)`, which silently returns an empty Series on DataFrames

**Reflex dashboard** (`reflex run`, `wtmw_reflex/wtmw_reflex.py`)
- Routes: `/` Übersicht, `/gaeste`, `/gaeste/[guest]` (person profile, name URL-encoded; `personensuche` still serves the Gäste page), `/themen`, `/netzwerke`
- Data builders live in `reflex_dashboard_redesign.py` (all return JSON-friendly str/int dicts so Reflex can type the computed vars); `reflex_dashboard_data.py` keeps loading, filtering and network assets
- Shared filter bar (Zeitraum / Sendung / Gastkategorie) on every page except `/netzwerke`, which always shows the full data set (`network_pairs` is unfiltered on purpose)
- `INCOMPLETE_YEARS` in `reflex_dashboard_redesign.py` dims scraping-gap years in the timeline (currently 2025, 2026: no Lanz Jan–Jul, no Maischberger Jan–Aug 2025)
- Format clusters come from `"kind": "format"` in `topic_labels.json` (no hard-coded IDs); shown with a badge and never chosen as the default topic
- Guest party = **latest** known `party_norm`, not the most frequent (`prepare_guest_metadata` / `latest_party_map`)
- Recharts ignores `fill_opacity` on `rx.recharts.bar`; use a lighter `fill` colour instead
- After editing a helper module, restart `reflex run`: hot reload re-imports the app file but not imported modules
- `topic_label_mismatches()` logs stale labels at startup

## German Language Handling

### Party Normalization
The codebase handles numerous variations of German party names:
- "Bündnis 90/Die Grünen" has 7+ spelling variations normalized to canonical form
- Regex pattern for Greens: `B[^.]{0,10}90[^.]*?[gG]rün\w{1,2}`
- Other parties: CDU, CSU, SPD, FDP, AfD, BSW, LINKE, parteilos
- `PARTY_ALIASES` in `nlp_utils.py` and `PARTY_NORMALIZATION_MAP` in `scrape_talkshows.py` are deduplicated (no repeated keys)

### Show Name Normalization
- `_SHOW_NAME_NORMALIZATIONS` in `scrape_talkshows.py` maps all known capitalisation variants to the canonical show name
- Canonical name for Hart aber Fair: `"hart aber fair"` (all lower-case, as used on fernsehserien.de)
- Applied at parse time so `HartAberFair_data.json` always stores the correct value; no post-hoc fixes needed

### Date Formats Supported
- `DD.MM.YYYY` (standard German)
- `DD. Month YYYY` (e.g., "01. Dezember 2024")
- Requires `de_DE.UTF-8` locale for parsing (set at module level)

### Text Cleaning Strategies
- Unicode normalization: NFKC
- Umlaut folding: ä→ae, ö→oe, ü→ue, ß→ss for fuzzy matching
- Cologne Phonetics (optional dependency) for surname matching
- Title removal: Prof., Dr., MdB, MdEP, LL.M., etc.
- `_clean_name_core` splits on comma without requiring leading whitespace: `(?:\s+(?:–|—|als|-)\s+|,\s+)`

## Critical Implementation Notes

### BERTopic on Apple Silicon (MPS)
- Uses float16 precision on MPS to reduce memory usage
- Max sequence length capped at 256 tokens for descriptions (`AttributeError` silently ignored if model does not expose the attribute)
- Falls back to CPU if MPS runs out of memory; prints a visible warning when this happens
- Batch size auto-reduction: 64 → 32 → 16 → 8 → 4 → 2 → 1

### Topic Label Quality
- BERTopic's `topics.json` is post-processed after `save()` to write back the cleaned representations (role filter + dedupe), because `save()` otherwise persists the raw KeyBERTInspired output
- Human-readable overrides live in `data/topic_labels.json` — edit this file to rename topics without retraining
- `TOPIC_ROLE_STOP` filters job titles from both stored representations and description cleaning
- `LABEL_CONFIG` (no verbs) should be used when preparing texts for label computation
- Both unclassified states (BERTopic outlier topic=-1 and missing description topic=NaN) display as `"Nicht klassifiziert"` in the dashboard — there is only one label for "no topic"

### Unclassified Episodes — Root Causes
Two distinct situations produce "Nicht klassifiziert":
- **topic = NaN (no description)**: fernsehserien.de has no text for older episodes (mainly 2001–2009). BERTopic was never called. Cannot be fixed without an alternative data source.
- **topic = -1 (BERTopic outlier)**: episode has a description but HDBSCAN assigned it to the outlier cluster. Currently ~14% of analysed episodes (322 of 2,280); with the 42 episodes without description, ~16% of all episodes show as "Nicht klassifiziert". Can be reduced by running `topic_model.reduce_outliers()` after training.

### Guest Consolidation
- `consolidate_guests()` aggregates on `party_norm` and `role_clean`, not on raw `party`/`role`
- Deduplication uses `_clean_name_core` which handles comma-separated role suffixes (e.g. "Jan van Aken, DIE LINKE")

### Network Visualization
- Node size: proportional to degree (appearances or shared guests)
- Node color: topic_range (viridis colormap) — lighter = more topic diversity
- Edge weight: number of co-occurrences
- Requires PyVis for interactive HTML exports; gracefully degrades if unavailable

### Data Integrity
- All episode scraping checks date is not in future before saving
- UID-based deduplication prevents reprocessing existing episodes
- Guest name cleaning is multi-stage with rejection reason tracking
- Manual name corrections supported via `data/name_corrections.json`

## Common Tasks

**Add a new talkshow**:
1. Add URL to `scrape_talkshows.py`
2. Add any capitalisation variants to `_SHOW_NAME_NORMALIZATIONS`
3. Create JSON loader and add to `all_data` aggregation
4. Add scraping call in `main()`
5. Update show_files list in `analyze_talkshows.py`

**Retune BERTopic**:
- Delete `data/best_parameters.json`
- Run `python analyze_talkshows.py` (tuning will auto-trigger)
- Results saved to `bertopic_tuning_results.csv` with all combinations tested
- Note: `clean_description_for_labels` uses `LABEL_CONFIG` (no verbs) for cleaner label candidates

**Reduce BERTopic outlier rate**:
- After training, call `topic_model.reduce_outliers(docs, topics)` with strategy `"embeddings"` or `"c-tf-idf"`
- Update topic assignments in the DataFrame before saving to Excel
- No retraining needed

**Rename a topic**:
- Edit `data/topic_labels.json`: `{"3": "Neuer Name"}`
- Restart Streamlit — no retraining needed

**Mark a cluster as a show format (not a topic)**:
- Some BERTopic clusters group guest roles / show formats (e.g. Markus Lanz episodes) rather than a subject
- In `data/topic_labels.json` give the entry `"kind": "format"`; it is shown as `"Format-Cluster: <label>"` and excluded from topic rankings ("Top-Thema", top-topic chart). The flag follows the label through `topic_labels.remap_topic_labels`
- `_TOPIC_GROUPS` in `reflex_dashboard_data.py` is keyed by curated **label text**, not topic ID (IDs change on every retraining)
- After a retraining outside the pipeline, remap labels with `topic_labels.update_topic_labels_file` — `topic_labels.json` must always match the model in `data/talkshow_topic_model/`

**Fix misidentified guests**:
1. Add entries to `data/name_corrections.json`: `{"Wrong Name": "Correct Name"}`
2. Rerun `python analyze_talkshows.py`

**Update stopwords**:
- Generic stopwords: edit `GERMAN_EXTRA_STOP` in `nlp_utils.py`
- Role/job title filter: edit `TOPIC_ROLE_STOP` in `nlp_utils.py`
- Changes affect both `clean_description_for_labels()` and `_filter_topic_terms()`

**Improve guest classification**:
- Rule-based: extend `RULES` in `guest_classification.py`
- Embedding fallback: adjust `CATEGORY_PROTOTYPES` or `CATEGORY_MIN_SIMILARITY_OVERRIDES` in `guest_classification_embedding.py`
- Compare results: `python scripts/compare_classification.py`

## Utility / Diagnostic Scripts

All diagnostic scripts live in `scripts/`:

- `compare_classification.py` — compares rule-based vs. embedding classification side-by-side
- `inspect_citizens.py` — deep analysis of "Citizens & Everyday Voices" category distribution
- `compare_topic_labels.py` — compares c-TF-IDF labels vs. KeyBERTInspired re-ranking
- `test_ngram_labels.py` — tests unigram / bigram / trigram c-TF-IDF labels on existing topic assignments
- `sync_guest_validation_overrides.py` — syncs manual guest validation overrides

## File Structure Patterns

- Python scripts use `BASE_DIR = Path(__file__).resolve().parent` for path resolution
- Data always goes to `data/` subdirectory; snapshots/backups go to `data/snapshots/`
- JSON for intermediate storage, Excel (`.xlsx`) for human-readable exports
- HTML visualizations use `.html` extension
- Network formats: `.png` (static), `.html` (interactive), `.gexf` (Gephi export)
- Diagnostic/utility scripts live in `scripts/`, not the project root
